### A correction to this report's own C4 diagnosis

C4 asserted that the 31-vs-29 gap was caused by onset hours whose prediction is
`NA` being dropped by the validity filter. **That was wrong.** Instrumenting the
filter showed `n_events_dropped_na = 0` for every variant and model: nothing is
lost that way. The real mechanism is in `attach_labels()` — an onset falling
after a stay's last observed hour is coded as right-censoring rather than as an
event, which is the same horizon rule the development cohort applies at 72 h and
is correct. Two of Variant B's onsets fall that way; A and C lose none, which is
why only B differs. The defect was never the arithmetic; it was that a
defensible rule went undocumented and produced two counts an examiner would
read as a contradiction. The thesis now states it, and the stage-08 change
records it in the data.

### C2. Decision-curve net benefit: the prose contradicts the table above it, three times out of three

This is the most damaging finding in the round. It is a Results-chapter table
and the paragraph that reads it, on the same page.

**Location.** `thesis/evaluation.tex` — Table `tab:net_benefit` (lines ~505–541)
and the paragraph at lines **545–547**.

| | Table (`\pcSnbPrimary*`, from `11_net_benefit_at_prevalence.csv`) | Prose |
|---|---|---|
| Variant A | **0.407** (40.7 %) | "**38.0 %** (Variant A)" |
| Variant B | **0.380** (38.0 %) | "**15.0 %** under Variant B" |
| Variant C | **0.411** (41.1 %) | "**39.9 %** (Variant C)" |

**Current value.** `11_net_benefit_at_prevalence.csv`, `snb` column, primary
model: A `0.407065`, B `0.379545`, C `0.411225`.

**Likely cause.** A survived rebuild. A's stated figure is B's *current* value,

value anywhere in the current result set** — they date from a run before the
Amendment-3 fit repair, when Variant B's model was separated and its net
benefit genuinely collapsed.

**Why it is critical, beyond the arithmetic.** The sentence does not merely
misreport three numbers; it reports a **qualitative pattern that no longer
exists**. It presents Variant B as a distant outlier at 15 % against ~39 % for
A and C. In the current results the three variants sit within 3 percentage
points of each other and B is the *middle* value. The paragraph then builds on
that false pattern — "This is genuine, if modest, value over both defaults" —

### C3. The event-rate table prints one variant's denominator in all three antibiotic-only rows

**Location.** `thesis/evaluation.tex` Table `tab:external_rates` (lines 862–892);

## 7. The screening that stops this recurring

The findings in §§1–2 fall into five classes, and **four of the five are
mechanically detectable**. This is the part of the plan that matters, because
round 10 ran the same audit by reading and missed C2, C3, C5 and C6 — reading
does not scale to 155 pages and 1,346 macros. Build the checks, wire them into
`build.sh`, and the class cannot come back.

Constraint respected throughout: **no new pipeline stages** (standing author
instruction). Everything below is a standalone check script or an addition to
`thesis_constants.R`, invoked from `build.sh`.

### 7.1 Build gate on unresolved macros — catches C1

Add to `thesis_constants.R`, at the end of generation:

```r
missing <- names(REGISTRY)[vapply(REGISTRY, identical, logical(1), "\\pcMissing")]
if (length(missing) && !nzchar(Sys.getenv("V2_ALLOW_MISSING"))) {
  stop(sprintf("%d macros unresolved: %s\nRe-run the producing stage, or set V2_ALLOW_MISSING=1 for a draft build.",
               length(missing), paste(missing, collapse = ", ")))
}
```

and to `build.sh`, before `pdflatex`:

```bash
grep -q 'newcommand{\\pc[A-Za-z]*}{\\pcMissing}' pipeline_constants.tex && {
  echo "REFUSING TO BUILD: unresolved macros in pipeline_constants.tex"; exit 1; }
grep -rq '\\pcMissing' table_*.tex && {
  echo "REFUSING TO BUILD: a generated table body is a placeholder"; exit 1; }
```

The `\pcMissing` mechanism was designed to make a gap visible. It works — and
then the PDF was committed anyway. The gap must block the build, not decorate
it.

### 7.2 Literal-number linter — catches C2, C5, C6, and makes the Declaration true

New file `project/check_thesis_literals.R` (or Python; either is fine), run from
`build.sh`. For each `thesis/*.tex`, after stripping comments,
`\cite*`/`\ref`/`\label`/`\includegraphics` arguments, TikZ coordinates and
style blocks, colour definitions, lengths (`pt`, `em`, `cm`, `\textwidth`) and
everything inside `\pc[A-Za-z]+`: flag every remaining decimal, every
thousands-separated integer, and every `\d+\\%`.

Maintain **`thesis/literals_allowlist.tsv`** — `file  line  literal  reason` —
with exactly three admissible reasons:

1. **prior work** (Moor 0.085/0.846/0.761, Wang ±0.381/−0.164, Wong 0.82–0.92,
   Cohen 867–2,178, …);
2. **pre-registered constant** (0.02, 0.03, 0.05, $q$ = 0.05, $m$ = 6, $B$ =
   2,000, seed 42);
3. **structural** (year ranges, section numbers, `45 CFR 46.104`, page
   geometry).

**No entry may be a study result.** Fail the build on any unallowlisted hit.
The initial run will produce the list in C5; work it down to zero
result-bearing entries. When it is at zero, the Declaration's sentence is true
by construction rather than by assertion — which is the only basis on which a
signed statement should stand.

### 7.5 Caption re-read protocol — the only class that cannot be automated

Run both before any commit touching `thesis/*.tex`, alongside the two sweeps

**Defensible with major revisions.** Not submittable in its current state.

current through seven disclosed amendments, the four non-confirmations are
