## 3. Stale captions — one confirmed, one more found, and the structural answer

**Are captions inside the pipeline-generated guarantee? No.** The guarantee
covers *values*: `thesis_constants.R` emits `\pc` macros and a missing quantity
typesets as a red `??`. A caption is ordinary prose, so a *number* in a caption
is protected only if it is written as a macro, and a *qualitative claim* in a
caption ("both are of similar size") is protected by nothing at all. That is
exactly how Figure 5.9's caption survived the reversal. There is no mechanism
that could have caught it; only a read.

Fixed:

- **`evaluation.tex` fig:label_variance_auroc** — "Both are of similar size"
  replaced with the two spreads as macros (`\pcSpreadLabel` vs
  `\pcSpreadModelClass`) and the statement that the model contribution is
  larger by roughly an order of magnitude, which is the reverse of H1's
  prediction. The claim is now expressed in quantities that move with the
  pipeline.
- **`discussion.tex`** — a second, worse survivor, and prose rather than a
  caption: "the defensible finding is the more interesting one: two sources of
  variance of comparable size". That directly contradicted H1's reversal.
  Rewritten to state the non-overlapping intervals and to locate the label's
  consequence in cohort membership rather than in discrimination.
- **`introduction.tex`** — "ignoring three others of similar size" asserted the
  premise as fact in the motivation. Reframed as the open question the thesis
  sets out to settle with intervals attached.

Swept and cleared: `comparable`, `similar size`, `slightly exceeds`, `same
order`, `label dominates`, `no patient develops`, `inflates AUROC`, `transports
intact`, `harder than either limb`. The remaining hits are legitimate — they
describe prior work's claim, the study's stated expectation, or an explicit
negation.

### 5b. "Why does H2 carry no uncertainty?" — now cheaply fixable, and the code is written

The intractability argument was never quite the whole story. The specific
obstacle is narrow: `sandwich` ships a `bread` method for `nnet::multinom` but
**no `estfun` method**, so `vcovCL()` and `vcovHC()` both fail on that class —
which is why the original call failed silently inside a `tryCatch` and left
`vcov_robust` as `NULL` while the methodology claimed cluster-robust standard
errors.

**Implemented this round.** `utils.R` now supplies `estfun.multinom` (for row
*i* and non-reference category *k* the score is `x_ij (y_ik − p_ik)`, and
`multinom` already stores that residual matrix), registers it against the
`sandwich` namespace, and adds `multinom_vcov_cluster()`, which returns `NULL`
with a *logged reason* instead of failing silently. Stage 05 now fits with
`Hess = TRUE` and clusters on `stay_id`, saving
`05_vcov_cluster[_arm]_<variant>.rds`.

Verified on a synthetic multinomial before wiring: the scores sum to ~0 at the
optimum, and an unclustered unadjusted sandwich reproduces `vcov(fit)` to 2–3
significant figures.

**Not yet run on the real fits.** It needs one stage-05 pass per variant.
`Hess = TRUE` only computes the Hessian after the optimiser stops, so the
coefficients should be bit-identical, but that must be verified against the
canary rather than assumed:

```bash
cd sepsis/project && ./run_pipeline.sh 05 && ./run_pipeline.sh 07 12
```

Then check `12_confirmatory_tests.csv` still reads H1 −0.13755, H4 −0.01654,
H6 −0.01293. If any moved, the refit is not innocuous and the change should be
reverted rather than explained.

Two honest caveats to state if this is used in the thesis: with `decay > 0` the
result is the covariance of the **penalised** estimator (the bread is the
inverse penalised Hessian, so the two factors are consistent, but it is a
ridge-regularised sandwich and should be described as one); and it gives
intervals on *coefficients*, not on H2's count of unstable covariates, which is
a threshold rule applied across three separate fits and still has no analytic
variance. It answers "is this coefficient estimated precisely enough for a
2× change to mean anything", which is the question the examiner is really
asking.

## 7. Table margins

Seven tables and two flow diagrams crossed the right margin, not one. **TeX
never warned about any of them**, which is why they survived: a `tabular` is
typeset at its natural width, so it has no target width to be overfull
*against*. `\hbox` warnings cannot detect this class of defect. They were found
by measuring glyph positions in the built PDF against the footer's right edge.

Before: 23 pages with content past the right margin, worst +125 pt.
After: 1 — the title page, whose `\newgeometry` right-flush logo is the ATU
template's intended layout.

Fixed:

- `adjustbox` added; `max width=\textwidth` wraps the wide tabulars (5.9, 5.10,
  5.12, 5.17, 5.19, 3.2) and both TikZ flow diagrams. It scales only when the
  natural width exceeds the text block and is inert otherwise.
- The four generated equity tables are wrapped at the `\input` site, so
  `write_table()` in `thesis_constants.R` is untouched and still emits complete
  `tabular` environments.
- **Table 3.3** (the one named in the feedback) fixed structurally rather than
  by scaling: the last column became a `p{3.1cm}` ragged-right column and two
  labels were shortened.
- Long `\texttt{}` file names have no break points and were running into the
  margin in body text. `\emergencystretch` set to 3 em, plus `\allowbreak` in
  the one remaining offender, following the idiom already used elsewhere in the
  document. (`hyphenat[htt]` was tried first and rejected: it fixed the
  overflow but introduced 31 font-shape substitution warnings.)

Build after all changes: **0 errors, 0 undefined references, 0 undefined
citations, 155 pages**, 1,337 macros with 0 missing.
