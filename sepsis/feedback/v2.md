## 0. Executive summary

**The reviewer's conclusion is correct. Variant B's primary-model fit is broken,
and Chapter 5 reverses.**

The reviewer's *stated test* — "if A and B overlap by 90% or more, a 0.153 gap
cannot be a label effect" — is **not met**: Jaccard(A, B) = 0.199, κ = 0.267. A

## 2. The four requested diagnostics

### 2.1 Convergence status and warnings

**There were no warnings, and that is itself the finding.**

`05_primary_model.Rmd` called `nnet::multinom(..., trace = FALSE, maxit = 500)`
with no `decay`. Reading the stored fits back:

| Variant | `fit$convergence` | Deviance | max\|coef\| | Binary fallback used? |
|---|---|---|---|---|
| A | **0** (converged) | 461,550.1 | 13.57 | no |
| B | **0** (converged) | 546,978.2 | 9.61 | no |

Both report clean convergence. The flag is worthless here: on a separated
likelihood the optimum is at infinity, so BFGS's relative-change stopping rule
fires at an arbitrary point that carries no information about identification.

The stage-05 log holds no A/B/C fit lines at all — the 2026-08-02 `V2_VARIANTS=D,E`
run overwrote it. The only warning in that log is the unrelated
`vcov_robust failed: no applicable method for 'estfun'`, i.e. **the
cluster-robust sandwich SEs silently failed for every multinomial fit**
(`sandwich::vcovHC` has no `estfun` method for `multinom`). The methodology
section claims cluster-robust SEs for the primary model; they were never
computed. This is a fourth defect, recorded in §6.3.

**Proof of separation.** Refitting the sepsis hazard by IRLS at a tight
tolerance, which BFGS's loose stopping rule masks:

```
Variant B: design rank 27 of 27, condition number 1.1e5
           glm.fit converged=TRUE at iter 62, warning: fitted probabilities
           numerically 0 or 1 occurred
           ALL 27 coefficients diverge together to |b| ~ 1e12 .. 1e15
Variant A: same picture, iter 112, |b| ~ 1e11 .. 1e15
```

The whole coefficient vector scaling together is the signature of complete
separation along a direction in covariate space — not a single bad predictor.
The design is full rank, so this is separation, not aliasing.

## 3. The evidence that settles it

Since the overlap test does not apply, three other lines were run.

### 3.1 Cross-application — the decisive test

Each fitted model's risk score scored against each variant's labels, on the
**479,271 test person-hours common to all three grids**:

| score \\ label | A | B | C |
|---|---|---|---|
| **model A** | 0.7659 | **0.7497** | 0.7493 |
| **model B** | 0.5929 | **0.6021** | 0.6024 |
| **model C** | 0.7690 | **0.7563** | 0.7590 |

model B is simply a bad model.**

## 4. Root cause

Three linked defects, in causal order:

1. **No physiological plausibility filter** (§6.2). The training panel contains
   heart rate up to 5,113,280, MAP down to −9,806 and up to 8,999,090, SpO2 up
   to 9,765,430. These are infinite-leverage rows and are the most likely
   proximate cause of the separation.
2. **Complete separation** of the multinomial likelihood, hence no finite MLE.
3. **`decay = 0`** — no penalty to restore identification, and `trace = FALSE`
   with no post-fit check, so nothing was ever reported.

`nnet::multinom`'s `convergence = 0` gave false assurance at every step.

## 6. Independent defects found while diagnosing

### 6.1 Heart rate was absent from every fitted model

`CHART_ITEMIDS` names the column `heart_rate`; every feature list in 05, 06 and
08 asks for `"hr"`. Selection was `intersect(FEATURES, names(dt))`, which drops
non-matching names **silently**. Consequences, all confirmed in the data:

- `hr` and `hr_slope6h` absent from the **primary model, the GBT and the Cox
  model** — 27 terms fitted where 29 were specified.
- `hr_slope6h` was never computed at all (stage 03's `slope_cols` uses the same
  `intersect`), so the column does not exist in any person-hours file.
- `heart_rate` was never forward-filled (7.5% NA) and never cleaned.
- **`news2_hr` is constant 0** — the NEWS2 heart-rate component never fires.
- **`sirs_score` maxes at 3, not 4** — the SIRS heart-rate criterion never fires.

So the thesis reports NEWS2 and SIRS as comparators with one component of each
disabled, and reports a "vitals-based" model that never saw the most-used vital
sign in sepsis. eICU is unaffected (stage 08 builds its panel with `hr`), which
means internal and external cohorts were **not** feature-matched either.

### 6.2 No plausibility filter existed

HANDOFF §4 states "FiO2 stored as percent → ÷100, clip [0.21, 1.0]" and "MAP
outliers to 117120 → clip [10, 250]". **Only the ÷100 was implemented.** No
clipping existed anywhere in the pipeline. Observed in
`03_person_hours_B.parquet`:

| Variable | Min | p99.9 | Max |
|---|---|---|---|
| heart_rate | 0 | 154 | **5,113,280** |
| resp_rate | 0 | 45 | **7,000,400** |
| spo2 | **−272** | 100 | **9,765,430** |
| map | **−9,806** | 156 | **8,999,090** |
| temp_c | **−17.8** | 39.6 | **2,686** |
| fio2 | 0 | 1.0 | **40.5** |

662 negative MAP values and 238 negative temperatures reached the models.

### 6.3 Cluster-robust SEs were never computed

`sandwich::vcovHC()` has no `estfun` method for class `multinom`, so the call in
stage 05 failed with a caught warning on every variant and `vcov_robust` was
`NULL`. The methodology section's claim of cluster-robust standard errors for
the primary model is not currently supported by the code. Not fixed in this
amendment — flagged for decision, since H2 is the only thing that would use
them and H2 needs rebuilding anyway.

> Stage 02 defines onset as the hour when the infection criterion and the SOFA

> onset as the earlier of suspicion time and the SOFA time […] Your conjunction
> definition removes that branch. […] The fix is not to delete the observation
> […] but to split it in two. State the definitional part analytically […] Then
> run the empirical version using min(suspicion time, SOFA time) and report how
> many onsets actually do precede first antibiotics, and what performance looks
> like in that window. That number is the contribution.

**The reviewer is correct on every count, including the sharper version of the

## 12. Diagnosis

### 12.1 The claim is worse than "circular" — it is a theorem

Reading `02_cohort_labels.Rmd` back:

```r
susp[dt_abx_before_cul >= 0, t_susp := pmax(abx_time, culture_time)]   # the LATER of the pair
...
onset_time := fifelse(sofa_delta >= SOFA_INCREASE_THRESHOLD, t_susp, NA)
```

Two facts, both visible in four lines of source:

1. `t_susp` is `pmax(abx_time, culture_time)` — the **later** element of the
   qualifying pair, so `t_susp ≥ min(first_abx, first_culture) = t_anchor`.
2. The SOFA delta appears only inside `fifelse(...)` as a **membership gate**.
   The timestamp written is `t_susp` regardless of when the SOFA rise happened.

Therefore `t_onset ≥ t_anchor` for **every** labelled stay under A, B, C and E.
The pre-treatment window is empty as a matter of arithmetic. This is stated in
the thesis as **Proposition 7.1 with a two-line proof**, not as a result.

The exact one-sided upper bound the thesis reported for the zero
(1.7 × 10⁻⁵ per person-hour) is arithmetically correct and informationally
empty: it bounds a quantity the definition fixes at zero.

### 12.2 The absolute claim was already contradicted by the thesis's own citation

The reviewer's point about `wong2026epic` lands. The Epic Sepsis Model v2
evaluation scores against a composite of clinician recognition and reports
encounter-level AUROC 0.80–0.90 with **median lead times of 1.4–7.1 h ahead of
clinician recognition** across four sites. "No patient develops sepsis before
doctors begin treatment" is not defensible in general and is **withdrawn** from
the abstract, C2, the H3 box, the discussion and the conclusion.

### 12.3 Amendment 2 rejected the right definition for the wrong scope

## 17. The normalisation defect

### 17.1 Where it actually lived

`utility_score.py` is not what produced any number in the thesis.
`07_metrics_suite.Rmd::compute_utility_score()` is, and it carried the same
defect, so both were fixed and the Python module is now a maintained mirror of
the R rule rather than a divergent second implementation. `design.tex` claimed
the Utility Score was computed "via Python module `utility_score.py`"; that
claim was false and has been corrected.

### 17.2 The defect

Both implementations computed

```
utility_normalised = U_total / U_max,      U_max = 1.0 per sepsis stay
```

A stay with no alert in the reward window contributes `U_FN = -1`, so a model
that never alerts scores `-n_sep / n_sep = -1.000` exactly. That is what
Table 5.3 reported for the primary model under all three variants — and the
primary model's largest predicted hourly probability is 0.0988, so at a 0.5
cut-off it never alerts at all. It **is** the inaction strategy and must score
0.

Reyna et al. (2020) normalise against two reference strategies, not one:

```
U_inaction = U_FN         x n_sep     (never alert)
U_optimal  = U_TP_MAX_REW x n_sep     (perfect, no false alarms)
normalised = (U - U_inaction) / (U_optimal - U_inaction)
```

The inaction baseline has to appear in **both** numerator and denominator. With
it, 1 is a perfect forecaster, 0 is exactly the no-alert strategy, and negative
is worse than silence — which is what methodology §3.10.1 always claimed.

### 17.3 A second defect in the same function, found while fixing the first

```r
lead <- onset_h - min(tp_early)                                  # max lead achieved
u    <- max(0, (PREDICTION_HORIZON_H - lead) / PREDICTION_HORIZON_H)
```

The reward window is `[onset-6, onset]`, so `lead` ranges 0–6 and
`u = 1 - lead/6`. **A model alerting six hours ahead scored 0; one alerting at
the moment of onset scored 1.** The sign is inverted with respect to the
metric's entire purpose, and it contradicts the Python module's own comment
("Best TP = earliest, most lead time") — the code deliberately selected the
earliest alert and then paid it the least. Corrected to `u = lead / 6`.

### 17.4 Verification

Before the run, `utility_curve()` was cross-checked against a brute-force
per-stay reference written directly from the definition, at seven thresholds on
Variants B and C: agreement to `< 1e-9` everywhere. That check was a one-off;
what is durable is that two invariants are now asserted inside stage 07 and
**stop** the pipeline rather than warn:

- a threshold above every predicted probability must score **exactly 0**;
- no operating point may exceed **1**.

The Python implementation was cross-checked against the R sweep output over the
full 61-point Variant B grid: identical to 4e-4, the residual being a single
tie at one threshold boundary.

## 18. The threshold sweep

### 18.1 Design

The grid is defined on the **alert rate** (fraction of person-hours alerted),
not on the probability scale: at a 0.19 % hourly event rate a probability grid
would evaluate nothing but the no-alert strategy for a calibrated model. Sixty
logarithmically spaced points span alert rates 1e-5 to 0.5, plus 0.5 itself so
the sweep table always contains the operating point used elsewhere. Constants
live in `config.R` (`UTILITY_SWEEP_*`).

`utility_curve()` scores the whole grid in one pass. The per-stay reward is
monotone in a falling threshold, so it costs one sort plus a single traversal
of the reward-window rows (6,273 of them for Variant B) — the sweep is cheaper
than the single-threshold loop it replaced.

Outputs: `07_utility_sweep.csv` (full grid, 2,036 rows),
`07_utility_max.csv` (attaining operating points), five new columns on
`07_metric_results*` (`utility_max`, `utility_opt_threshold`,
`utility_opt_alert_rate`, `utility_opt_burden`, `utility_opt_detection`), and
`figures/07_utility_threshold_sweep.png`.

### 22.2 Confirmation of the bug signature

|---|---|---|---|---|

The cause was two lines apart in the source. Line 206 fixed the variant:

```r
v <- LABEL_VARIANTS[["B"]]     # hardcoded
```

and line 323 looped over all three:

```r
for (vid in names(LABEL_VARIANTS)) { ... }   # swaps the MODEL only
```

The loop read `05_model_primary_<vid>.rds` and `06_model_gbt_<vid>.rds` per

"variants" were one Variant-B label evaluated by three different models.

### 22.3 The defect that made it invisible

`evaluation.tex` had explained the identity away:

> NEWS2 is label-invariant (identical AUROC across all variants on eICU)
> because it uses only physiological signals

The sentence is a true statement about the wrong object. NEWS2's **predictor**
is label-invariant — it is computed from physiology once. Its **AUROC** cannot
be, because AUROC is a property of the predictor *and* the outcome vector it is
ranked against. Internally NEWS2 does score differently under A/B/C
(0.6415 under B). The thesis had taken the signature of a missing computation
and written it up as a property of the comparator, which is the worst possible
outcome: the defect became load-bearing prose.

This is the generalisable lesson, and it is now in HANDOFF §4: **when a loop is
supposed to vary factor X, identify a quantity that must move when X moves and
assert at run time that it does.**

### 22.4 The other five defects

Found while fixing the first, all in the same chunk, all confirmed in source.

**(a) The anchor required a culture, and the thesis said it did not.**
Line 209 was an inner `merge(eicu_abx, eicu_culture, by = "stay_id")`, guarded
by `nrow(eicu_culture) > 0`. So suspicion required **both** limbs.
Meanwhile `evaluation.tex` said:

> eICU-CRD's microbiology coverage is too sparse to reproduce the Sepsis-3
> anchor, so infection is triggered on antibiotics alone

and HANDOFF §4 said the same. **Neither was true of the code.** The documented
mitigation was never implemented. Documentation and implementation had
disagreed on this point for the whole project, and the disagreement was in the
direction that made the result look better than it was.

`microLab.csv.gz` holds 16,996 rows over **2,923 distinct unit stays** — about
1.4 % of the cohort. So ≥ 98.6 % of the 7.87 M person-hours were in stays where
the Sepsis-3 conjunction could not fire under any variant, whatever the
patient's physiology. That, not epidemiology, is the bulk of the 8-per-million
rate.

**(b) Only one of the two drug tables was read.** `medication.csv.gz` only;
`infusionDrug.csv.gz` (48 MB) was never opened. Vancomycin,
piperacillin-tazobactam and cefepime are routinely infusions. This is exactly
the cause the feedback named.

**(c) Negative culture offsets deleted whole stays.** `culturetakenoffset` is
frequently negative (pre-ICU draws; the first two data rows are −688 and
−5481). Then `t_susp_h = pmax(abx_hour, culture_hour) < 0`, so
`hour == onset_hour` never matched **and** `at_risk <- is.na(onset_hour) | hour
<= onset_hour` was FALSE for every hour, so `grid <- grid[at_risk == TRUE]`
removed the stay entirely. MIMIC's rule is that an onset outside
`[intime, outtime]` becomes `NA` and the stay **remains** in the at-risk
denominator as non-septic. eICU was silently shrinking its own denominator.

**(d) The SOFA criterion was not MIMIC's criterion.** MIMIC gates on a SOFA
**delta ≥ 2 against a baseline** (admission for A/B, rolling-24 h for C)
aggregated over the variant's evaluation window. eICU gated on an **absolute**
`sofa_total >= 2`, evaluated per row, with no baseline, no window and no
variant parameters. Because `score_sofa()` substitutes assumed-normal values
for missing components, an absolute threshold rejects on *missingness* — and it
was applied in the database with the sparser labs, so the bias ran towards
fewer events. It also nulled a stay-level `onset_hour` row by row, which
corrupts the at-risk set independently of everything else.

**(e) NEWS2 charged every eICU person-hour a spurious +3.**
`avpu_alert <- !is.na(gcs) & gcs >= 14` maps unmeasured to `FALSE`, and
`news2()` scores `FALSE` as 3 while scoring `NA` as 0. eICU has no GCS in
`vitalPeriodic`, so this was **every row**. Constant, therefore invisible in
AUROC — but it moves the whole score distribution and invalidates every
threshold, specificity and alert-burden figure compared across cohorts, which
is precisely what `11_external_operating_points` does.

## 24. Action-derived features in the predictor set

### 24.1 The feedback

> Your features contain the very clinical actions you are critiquing.
>
> You argue the label is constituted by clinician action, but vasopressor
> indicators and the per-test "was this lab ordered this hour" flags are
> themselves records of clinician attention. Five of the ten unstable features
> in Table 5.6 are exactly these. That is a more interesting result than you
> currently claim: it is the action-derived features that are unstable, not
> clinical physiology in general, which supports your central argument. Please
> run an ablation that drops vasopressor and order-flag features and report the
> performance change. This is a cheap experiment with a high return.

The substantive point is correct and the thesis was under-claiming. The
arithmetic in the second sentence is not, and the correction runs in the
feedback's favour.

### 24.2 The counts, checked against source

`12_h2_coefficient_stability.csv` carries 22 covariates, of which **6** are
unstable — not ten. Table 5.6 has six rows. Their composition:

| Covariate | What changed | Kind |
|---|---|---|
| `bilirubin_total` | sign reversal | physiological |
| `platelets` | magnitude ≥2× | physiological |
| `vaso_anyTRUE` | sign reversal **and** magnitude ≥2× | **action-derived** |
| `creatinine_measured` | magnitude ≥2× | **action-derived** |
| `platelets_measured` | magnitude ≥2× | **action-derived** |
| `wbc_measured` | magnitude ≥2× | **action-derived** |

So **4 of 6**, not 5 of 10. But the rate is what matters, and the rate is
stronger than the raw count suggests:

| Feature kind | Covariates | Unstable | % |
|---|---|---|---|
| Action-derived | 8 | 4 | **50.0** |
| Physiological | 14 | 2 | **14.3** |

Action-derived features are **36 % of the specification and 67 % of the
unstable terms** — a 3.5-fold higher instability rate. The feedback's reading
("it is the action-derived features that are unstable, not clinical physiology
in general") is supported, and by a wider margin than the miscount implied.

Honesty about what this is not: with 22 covariates the counts are small and the
difference between 50.0 % and 14.3 % is not established at any conventional
confidence. H2 carries no test statistic by construction (the stored multinomial
fit has no Hessian and refitting under a bootstrap is intractable at 2.3 M
training rows), so the split inherits that limitation. The thesis says so
explicitly rather than dressing a 4-vs-2 count as an inferential result.

### 24.3 Why the ablation was still needed

A concentration of *instability* is not evidence of *dependence*. The features
could be unstable precisely because they contribute little, with their
coefficients free to wander. Distinguishing that from "the model leans on
clinician behaviour" requires removing them and refitting, which is what the
feedback asked for.

There is a second, larger reason. The thesis's central claim — that the sepsis
label is constituted by clinician action — invites the objection that
*everything* in an ICU dataset is, so the claim is unfalsifiable and therefore
empty. The ablation converts it into something testable: the feature set is
divided in advance into predictors that record the patient and predictors that
record the clinician, and the two are shown to behave differently under a change
of label. That is a materially stronger position than the one the thesis held.

### 24.4 What was built — Protocol Amendment 5

**`config.R`**
- `ACTION_DERIVED_FEATURES`: the 8 covariates (`vaso_any`, `norepi_epi_any`,
  and the six `*_measured` order flags).
- `active_arms()` / `arm_features()` / `arm_suffix()` — the arm mechanism,
  deliberately mirroring the existing `active_variants()` idiom.

**The boundary, and why it is where it is.** Forward-filled laboratory
*values* are **retained**, even though a value exists only because someone
ordered the test. Dropping them too would remove most of the laboratory signal
and confound the ablation with a loss of physiological information. What is
removed is the set of features that encode *only* clinician behaviour. This is
the conservative choice and it is stated as a limitation in the thesis rather
than glossed. Do not widen it later without re-reading that reasoning.

**`utils.R`**

## 30. Point 9 — Chapter 4 reads as an inventory

### 30.1 The point, and what it was right about

Chapter 4 listed the twelve stages and their outputs and never said why the
architecture takes that shape. The English-not-code judgement it endorses was
already being followed and is unchanged; what was missing was the rationale, and

### 30.2 New §4.1 "Design Principles"

Four constraints, each stated as constraint → decision → what the decision rules
out. Written to be defensible under questioning rather than descriptive:

| Principle | The argument made |
|---|---|
| **Streaming, and read-only sources** | `chartevents` 3.5 GB / `labevents` 2.6 GB exceed working memory expanded. DuckDB pushes the cohort and item filters into the scan. **The rejected alternative is the interesting half**: extracting a reduced copy once makes the extraction invisible downstream, so a filter defect becomes indistinguishable from a property of the data. Reading the originals every run keeps extraction inside the reproducible chain. Corollary: `data/` is never written; reproduction is "delete `output/`, re-run". |
| **One definition per constant** | A study that varies definitions deliberately cannot afford a constant that differs between two stages — such a divergence would be *indistinguishable from a finding*. `config.R` is the sole source of truth; `thesis_constants.R` extends the same discipline to the document. |
| **Interfaces fail loudly or not at all** | The dangerous failure is not a crash but a stage quietly doing less than asked. Named concretely: intersecting a declared feature list with present columns drops a mismatched predictor silently — model fits, metrics compute, nothing indicates a missing variable. Hence `require_features()` errors; hence the fit logs max\|coef\| beside the convergence flag, because a convergence flag alone cannot distinguish a converged fit from an unidentified one. The three run-time invariants (no-alert threshold scores exactly 0; no operating point exceeds 1; three variants must yield three distinct external onset sets) are **stops, not warnings** — "a warning in a sixty-minute batch run is a line in a log nobody reads." |
| **Expensive fits refreshable in isolation** | GBT fitting is not bit-stable, so an incidental refit moves numbers with no change of substance. `V2_VARIANTS` and `V2_ARMS` scope a run; additional arms write to separate files and cannot overwrite a pre-registered fit. |

Plus a closing paragraph, **"Why twelve scripts rather than one program"**: the
stage boundaries follow the analysis, not the code, because each corresponds to
a step a claim rests on. Stage 12 is the clearest case — it reads only stored
predictions, so the correction applied to a result is verifiable independently
of the model that produced it.

Note on voice: every one of these principles is a real trap this project hit,
but each is stated **analytically as a design rationale**, never as a repair. The
`intersect()` example is presented as the failure mode the interface discipline
exists to prevent, which is what it is.
