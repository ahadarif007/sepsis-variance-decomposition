## 0. Executive summary

**The reviewer's conclusion is correct. Variant B's primary-model fit is broken,
and Chapter 5 reverses.**

The reviewer's *stated test* — "if A and B overlap by 90% or more, a 0.153 gap
cannot be a label effect" — is **not met**: Jaccard(A, B) = 0.199, κ = 0.267. A
and B have similar event *counts* but are largely *different patients*. The
premise that they "identify almost the same patients" is false.

## 2. The four requested diagnostics

### 2.1 Convergence status and warnings

**There were no warnings, and that is itself the finding.**

`05_primary_model.Rmd` called `nnet::multinom(..., trace = FALSE, maxit = 500)`
with no `decay`. Reading the stored fits back:

| Variant | `fit$convergence` | Deviance | max\|coef\| | Binary fallback used? |
|---|---|---|---|---|
| A | **0** (converged) | 461,550.1 | 13.57 | no |
| B | **0** (converged) | 546,978.2 | 9.61 | no |

Both report clean convergence. The flag is worthless here: on a separated
likelihood the optimum is at infinity, so BFGS's relative-change stopping rule
fires at an arbitrary point that carries no information about identification.

The stage-05 log holds no A/B/C fit lines at all — the 2026-08-02 `V2_VARIANTS=D,E`
run overwrote it. The only warning in that log is the unrelated
`vcov_robust failed: no applicable method for 'estfun'`, i.e. **the
cluster-robust sandwich SEs silently failed for every multinomial fit**
(`sandwich::vcovHC` has no `estfun` method for `multinom`). The methodology
section claims cluster-robust SEs for the primary model; they were never
computed. This is a fourth defect, recorded in §6.3.

**Proof of separation.** Refitting the sepsis hazard by IRLS at a tight
tolerance, which BFGS's loose stopping rule masks:

```
Variant B: design rank 27 of 27, condition number 1.1e5
           glm.fit converged=TRUE at iter 62, warning: fitted probabilities
           numerically 0 or 1 occurred
           ALL 27 coefficients diverge together to |b| ~ 1e12 .. 1e15
Variant A: same picture, iter 112, |b| ~ 1e11 .. 1e15
```

The whole coefficient vector scaling together is the signature of complete
separation along a direction in covariate space — not a single bad predictor.
The design is full rank, so this is separation, not aliasing.

## 3. The evidence that settles it

Since the overlap test does not apply, three other lines were run.

### 3.1 Cross-application — the decisive test

Each fitted model's risk score scored against each variant's labels, on the
**479,271 test person-hours common to all three grids**:

| score \\ label | A | B | C |
|---|---|---|---|
| **model A** | 0.7659 | **0.7497** | 0.7493 |
| **model B** | 0.5929 | **0.6021** | 0.6024 |
| **model C** | 0.7690 | **0.7563** | 0.7590 |

Read down the B column: a well-behaved model reaches **0.75 on Variant B's
labels**. Read across the model-B row: model B scores 0.59–0.60 on *every*
label, including A's and C's. **B's label is as predictable as A's and C's;
model B is simply a bad model.**

## 4. Root cause

Three linked defects, in causal order:

1. **No physiological plausibility filter** (§6.2). The training panel contains
   heart rate up to 5,113,280, MAP down to −9,806 and up to 8,999,090, SpO2 up
   to 9,765,430. These are infinite-leverage rows and are the most likely
   proximate cause of the separation.
2. **Complete separation** of the multinomial likelihood, hence no finite MLE.
3. **`decay = 0`** — no penalty to restore identification, and `trace = FALSE`
   with no post-fit check, so nothing was ever reported.

`nnet::multinom`'s `convergence = 0` gave false assurance at every step.

## 6. Independent defects found while diagnosing

### 6.1 Heart rate was absent from every fitted model

`CHART_ITEMIDS` names the column `heart_rate`; every feature list in 05, 06 and
08 asks for `"hr"`. Selection was `intersect(FEATURES, names(dt))`, which drops
non-matching names **silently**. Consequences, all confirmed in the data:

- `hr` and `hr_slope6h` absent from the **primary model, the GBT and the Cox
  model** — 27 terms fitted where 29 were specified.
- `hr_slope6h` was never computed at all (stage 03's `slope_cols` uses the same
  `intersect`), so the column does not exist in any person-hours file.
- `heart_rate` was never forward-filled (7.5% NA) and never cleaned.
- **`news2_hr` is constant 0** — the NEWS2 heart-rate component never fires.
- **`sirs_score` maxes at 3, not 4** — the SIRS heart-rate criterion never fires.

So the thesis reports NEWS2 and SIRS as comparators with one component of each
disabled, and reports a "vitals-based" model that never saw the most-used vital
sign in sepsis. eICU is unaffected (stage 08 builds its panel with `hr`), which
means internal and external cohorts were **not** feature-matched either.

### 6.2 No plausibility filter existed

HANDOFF §4 states "FiO2 stored as percent → ÷100, clip [0.21, 1.0]" and "MAP
outliers to 117120 → clip [10, 250]". **Only the ÷100 was implemented.** No
clipping existed anywhere in the pipeline. Observed in
`03_person_hours_B.parquet`:

| Variable | Min | p99.9 | Max |
|---|---|---|---|
| heart_rate | 0 | 154 | **5,113,280** |
| resp_rate | 0 | 45 | **7,000,400** |
| spo2 | **−272** | 100 | **9,765,430** |
| map | **−9,806** | 156 | **8,999,090** |
| temp_c | **−17.8** | 39.6 | **2,686** |
| fio2 | 0 | 1.0 | **40.5** |

662 negative MAP values and 238 negative temperatures reached the models.

### 6.3 Cluster-robust SEs were never computed

`sandwich::vcovHC()` has no `estfun` method for class `multinom`, so the call in
stage 05 failed with a caught warning on every variant and `vcov_robust` was
`NULL`. The methodology section's claim of cluster-robust standard errors for
the primary model is not currently supported by the code. Not fixed in this
amendment — flagged for decision, since H2 is the only thing that would use
them and H2 needs rebuilding anyway.

## 11. The feedback

> Stage 02 defines onset as the hour when the infection criterion and the SOFA
> rise are both met. The infection criterion requires a qualifying
> antibiotic-culture pair. Your treatment-anchored window is defined as the hours
> before the first antibiotic or culture. Under those definitions, zero onsets in

> about your code, not a discovery about MIMIC-IV. […] The standard
> operationalisation, including Seymour et al. and the PhysioNet Challenge, takes
> onset as the earlier of suspicion time and the SOFA time […] Your conjunction
> definition removes that branch. […] The fix is not to delete the observation
> […] but to split it in two. State the definitional part analytically […] Then
> run the empirical version using min(suspicion time, SOFA time) and report how
> many onsets actually do precede first antibiotics, and what performance looks
> like in that window. That number is the contribution.

**The reviewer is correct on every count, including the sharper version of the
point.** Accepted in full and implemented as **Protocol Amendment 4**.

## 12. Diagnosis

### 12.1 The claim is worse than "circular" — it is a theorem

Reading `02_cohort_labels.Rmd` back:

```r
susp[dt_abx_before_cul >= 0, t_susp := pmax(abx_time, culture_time)]   # the LATER of the pair
...
onset_time := fifelse(sofa_delta >= SOFA_INCREASE_THRESHOLD, t_susp, NA)
```

Two facts, both visible in four lines of source:

1. `t_susp` is `pmax(abx_time, culture_time)` — the **later** element of the
   qualifying pair, so `t_susp ≥ min(first_abx, first_culture) = t_anchor`.
2. The SOFA delta appears only inside `fifelse(...)` as a **membership gate**.
   The timestamp written is `t_susp` regardless of when the SOFA rise happened.

Therefore `t_onset ≥ t_anchor` for **every** labelled stay under A, B, C and E.
The pre-treatment window is empty as a matter of arithmetic. This is stated in
the thesis as **Proposition 7.1 with a two-line proof**, not as a result.

The exact one-sided upper bound the thesis reported for the zero
(1.7 × 10⁻⁵ per person-hour) is arithmetically correct and informationally
empty: it bounds a quantity the definition fixes at zero.

### 12.2 The absolute claim was already contradicted by the thesis's own citation

The reviewer's point about `wong2026epic` lands. The Epic Sepsis Model v2
evaluation scores against a composite of clinician recognition and reports
encounter-level AUROC 0.80–0.90 with **median lead times of 1.4–7.1 h ahead of
clinician recognition** across four sites. "No patient develops sepsis before
doctors begin treatment" is not defensible in general and is **withdrawn** from
the abstract, C2, the H3 box, the discussion and the conclusion.

### 12.3 Amendment 2 rejected the right definition for the wrong scope

## 17. The normalisation defect

### 17.1 Where it actually lived

`utility_score.py` is not what produced any number in the thesis.
`07_metrics_suite.Rmd::compute_utility_score()` is, and it carried the same
defect, so both were fixed and the Python module is now a maintained mirror of
the R rule rather than a divergent second implementation. `design.tex` claimed
the Utility Score was computed "via Python module `utility_score.py`"; that
claim was false and has been corrected.

### 17.2 The defect

Both implementations computed

```
utility_normalised = U_total / U_max,      U_max = 1.0 per sepsis stay
```

A stay with no alert in the reward window contributes `U_FN = -1`, so a model
that never alerts scores `-n_sep / n_sep = -1.000` exactly. That is what
Table 5.3 reported for the primary model under all three variants — and the
primary model's largest predicted hourly probability is 0.0988, so at a 0.5
cut-off it never alerts at all. It **is** the inaction strategy and must score
0.

Reyna et al. (2020) normalise against two reference strategies, not one:

```
U_inaction = U_FN         x n_sep     (never alert)
U_optimal  = U_TP_MAX_REW x n_sep     (perfect, no false alarms)
normalised = (U - U_inaction) / (U_optimal - U_inaction)
```

The inaction baseline has to appear in **both** numerator and denominator. With
it, 1 is a perfect forecaster, 0 is exactly the no-alert strategy, and negative
is worse than silence — which is what methodology §3.10.1 always claimed.

### 17.3 A second defect in the same function, found while fixing the first

```r
lead <- onset_h - min(tp_early)                                  # max lead achieved
u    <- max(0, (PREDICTION_HORIZON_H - lead) / PREDICTION_HORIZON_H)
```

The reward window is `[onset-6, onset]`, so `lead` ranges 0–6 and
`u = 1 - lead/6`. **A model alerting six hours ahead scored 0; one alerting at
the moment of onset scored 1.** The sign is inverted with respect to the
metric's entire purpose, and it contradicts the Python module's own comment
("Best TP = earliest, most lead time") — the code deliberately selected the
earliest alert and then paid it the least. Corrected to `u = lead / 6`.

### 17.4 Verification

Before the run, `utility_curve()` was cross-checked against a brute-force
per-stay reference written directly from the definition, at seven thresholds on
Variants B and C: agreement to `< 1e-9` everywhere. That check was a one-off;
what is durable is that two invariants are now asserted inside stage 07 and
**stop** the pipeline rather than warn:

- a threshold above every predicted probability must score **exactly 0**;
- no operating point may exceed **1**.

The Python implementation was cross-checked against the R sweep output over the
full 61-point Variant B grid: identical to 4e-4, the residual being a single
tie at one threshold boundary.

## 18. The threshold sweep

### 18.1 Design

The grid is defined on the **alert rate** (fraction of person-hours alerted),
not on the probability scale: at a 0.19 % hourly event rate a probability grid
would evaluate nothing but the no-alert strategy for a calibrated model. Sixty
logarithmically spaced points span alert rates 1e-5 to 0.5, plus 0.5 itself so
the sweep table always contains the operating point used elsewhere. Constants
live in `config.R` (`UTILITY_SWEEP_*`).

`utility_curve()` scores the whole grid in one pass. The per-stay reward is
monotone in a falling threshold, so it costs one sort plus a single traversal
of the reward-window rows (6,273 of them for Variant B) — the sweep is cheaper
than the single-threshold loop it replaced.

Outputs: `07_utility_sweep.csv` (full grid, 2,036 rows),
`07_utility_max.csv` (attaining operating points), five new columns on
`07_metric_results*` (`utility_max`, `utility_opt_threshold`,
`utility_opt_alert_rate`, `utility_opt_burden`, `utility_opt_detection`), and
`figures/07_utility_threshold_sweep.png`.
